bestls CLI: File Type & Permissions Display

Currently, bestls shows Type in default mode and Permissions in -l/--long mode — but never both at once. We need a design that displays file type and user permissions simultaneously, with permissions shown in a more human-readable format.

Design Goals

Goal 1
Simultaneous Display
Show file type and permissions in one view, without needing a flag toggle
Goal 2
Human-readable Permissions
Replace cryptic -rwxr-xr-x with more intuitive formats for diverse user skill levels
Goal 3
Rich File Types
Expand beyond File/Dir to show Symlink, Pipe, Socket, Block/Char devices

Design Options

Four approaches, ranging from traditional to visual. Each shows the same sample directory listing.

Option A

Classic: Separate Type + Permission Columns

The traditional Unix approach: add an explicit Type column with rich type labels (File, Dir, Symlink, Pipe, Socket, Block, Char) alongside a Permissions column showing the standard 10-character string (-rwxr-xr-x). No breaking changes to existing -l behavior, just adds the Type column. 

┌─────────────┬──────────┬─────────────┬───────┬─────────────┐
│ Name         │ Type     │ Permissions │ Size   │ Modified    │
├─────────────┼──────────┼─────────────┼───────┼─────────────┤
│ .cargo       │ Dir      │ drwxr-xr-x  │ 4.1 KB │ 2 days ago  │
│ Cargo.lock   │ File     │ -rw-r--r--  │ 35 KB  │ 3 hours ago │
│ Cargo.toml   │ File     │ -rw-r--r--  │ 315 B  │ 3 hours ago │
│ README.md    │ File     │ -rw-r--r--  │ 2.3 KB │ just now    │
│ src          │ Dir      │ drwxr-xr-x  │ 4.0 KB │ 1 week ago  │
│ node -> ../n │ Symlink  │ lrwxrwxrwx  │ 9 B    │ 1 hour ago  │
│ test.sh      │ File     │ -rwxr-xr-x  │ 85 B   │ 2 hours ago │
└─────────────┴──────────┴─────────────┴───────┴─────────────┘

Pros

  • Familiar to experienced Unix users
  • Clean separation of concerns
  • Backward compatible with -l behavior
  • Type detects all file kinds (symlink, pipe, etc.)

Cons

  • 5 columns may be wide on small terminals
  • Permission string still cryptic to beginners
  • Type column duplicates info from Perms first char
Option B

Labeled: Type Column + Split Permissions

Same Type column as Option A, but permissions are presented in a labeled, human-readable format: u:rwx g:r-x o:r-- — clearly showing what the owner, group, and others can do. Designed to be self-documenting for users unfamiliar with Unix permission bits. 

┌─────────────┬──────────┬────────────────────┬───────┬─────────────┐
│ Name         │ Type     │ Permissions         │ Size   │ Modified    │
├─────────────┼──────────┼────────────────────┼───────┼─────────────┤
│ .cargo       │ Dir      │ u:rwx g:r-x o:r-x  │ 4.1 KB │ 2 days ago  │
│ Cargo.lock   │ File     │ u:rw- g:r-- o:r--  │ 35 KB  │ 3 hours ago │
│ Cargo.toml   │ File     │ u:rw- g:r-- o:r--  │ 315 B  │ 3 hours ago │
│ README.md    │ File     │ u:rw- g:r-- o:r--  │ 2.3 KB │ just now    │
│ src          │ Dir      │ u:rwx g:r-x o:r-x  │ 4.0 KB │ 1 week ago  │
│ node -> ../n │ Symlink  │ u:rwx g:rwx o:rwx  │ 9 B    │ 1 hour ago  │
│ test.sh      │ File     │ u:rwx g:r-x o:r-x  │ 85 B   │ 2 hours ago │
└─────────────┴──────────┴────────────────────┴───────┴─────────────┘

Pros

  • Self-documenting — no Unix knowledge required
  • Owner/Group/Other roles are explicit
  • Easy to audit: "who can do what?"
  • All file types supported

Cons

  • Very wide column — may not fit small terminals
  • Verbose: more noise than signal for power users
  • Abbreviation u/g/o still requires explanation
Option C

Hybrid: Combined Type+Perm Column (Compact)

A single Type & Permissions column that merges both pieces of information compactly. File type is indicated by a leading character (d/-/l etc.) followed by the permission bits, keeping the table at 4 columns. Permissions use the labeled format but squeezed into one string: drwxr-xr-x or the labeled variant d:rwx:r-x:r-x. 

┌─────────────┬──────────────┬───────┬─────────────┐
│ Name         │ Type & Perms │ Size   │ Modified    │
├─────────────┼──────────────┼───────┼─────────────┤
│ .cargo       │ d  rwxr-xr-x │ 4.1 KB │ 2 days ago  │
│ Cargo.lock   │ -  rw-r--r-- │ 35 KB  │ 3 hours ago │
│ Cargo.toml   │ -  rw-r--r-- │ 315 B  │ 3 hours ago │
│ README.md    │ -  rw-r--r-- │ 2.3 KB │ just now    │
│ src          │ d  rwxr-xr-x │ 4.0 KB │ 1 week ago  │
│ node -> ../n │ l  rwxrwxrwx │ 9 B    │ 1 hour ago  │
│ test.sh      │ -  rwxr-xr-x │ 85 B   │ 2 hours ago │
└─────────────┴──────────────┴───────┴─────────────┘

Pros

  • Most compact — only 4 columns
  • Familiar to ls -l users
  • Type symbol (d/-/l) is visually distinctive
  • Best for narrow terminals

Cons

  • Type indicator is subtle (single character)
  • Permissions format unchanged, still cryptic
  • Less scannable than separate columns
Option D

Visual: Type Badges + Color-coded Permissions

The most visually rich approach: file types shown as colored badges (Dir, File, Symlink) and permissions displayed as permission planks — colored blocks for each r, w, x bit, with green for present and dim for absent. Requires terminal color support (already available via owo-colors). This is the most beginner-friendly option. 

┌─────────────┬───────────┬───────────────────────┬───────┬─────────────┐
│ Name         │ Type      │ Permissions            │ Size   │ Modified    │
├─────────────┼───────────┼───────────────────────┼───────┼─────────────┤
│ .cargo       │  Dir  📁  │ [rwx][r-x][r-x]        │ 4.1 KB │ 2 days ago  │
│ Cargo.lock   │ File  📄  │ [rw-][r--][r--]        │ 35 KB  │ 3 hours ago │
│ Cargo.toml   │ File  📄  │ [rw-][r--][r--]        │ 315 B  │ 3 hours ago │
│ README.md    │ File  📄  │ [rw-][r--][r--]        │ 2.3 KB │ just now    │
│ src          │  Dir  📁  │ [rwx][r-x][r-x]        │ 4.0 KB │ 1 week ago  │
│ node -> ../n │ Link  🔗  │ [rwx][rwx][rwx]        │ 9 B    │ 1 hour ago  │
│ test.sh      │ File  📄  │ [rwx][r-x][r-x]        │ 85 B   │ 2 hours ago │
└─────────────┴───────────┴───────────────────────┴───────┴─────────────┘

In actual terminal: badges are colored (Dir=blue, File=white, Symlink=cyan). Permission bits: r/w/x = green (present), - = red (absent). Perms grouped in [] brackets per role: Owner/Group/Other.

Pros

  • Most intuitive — scan colors, don't read chars
  • Type badges + emoji are instantly recognizable
  • Permissions grouped by role ([rwx] per class)
  • Great on-boarding for beginners

Cons

  • Requires color terminal (already a dependency)
  • Emoji may render differently across fonts/terminals
  • Non-standard: breaks muscle memory of Unix users
  • Not copy-paste friendly without emoji support

Tentative Recommendation

Start with Option B (Labeled) as the default display, and offer Option A (Classic) or C (Hybrid) behind a --compact or --classic flag for power users who prefer compact output. Option D (Visual) can be layered on top of any format via color — the color enhancement is orthogonal to the column layout choice. This gives the best of both worlds: readable by default, compact when needed.
